# 2. 문제 생성과 측정 데이터 설계

상태: 설계 제안. 기존 v5 bank/응답/사람·AI 검토 기록을 수정하지 않는다.

## 2.1 복잡해지는 지점

프롬프트를 길게 만드는 것보다 ‘어떤 주장을 어떤 응답으로 뒷받침할 것인가’를 먼저 정한다.
각 문항은 한 가지 주 수행을 측정하고, 읽기 전/후 조건과 정답 근거가 명확해야 한다.

| 구분 | 사전 지식 진단 | 읽기 후 수행 평가 |
| --- | --- | --- |
| 목적 | 추천 시점의 독자 관찰 | 예상한 적합성/이해 가능성의 독립 검증 |
| 시점 | 추천 및 해당 자료 열람 전 | 지정 자료를 읽은 뒤 |
| 지문 | 답을 가르치는 설명 없음 | 평가 대상 자료 또는 고정한 읽기 경험 |
| 결과 사용 | 추천 입력으로 사용 | 첫 실험에서는 평가에만 사용 |
| 예시 | 벡터 집합의 독립성을 판별 | 읽은 절의 방법을 새로운 벡터 집합에 적용 |
| 금지 | 정답/규칙을 보여주고 사전 지식으로 집계 | 읽고 맞힌 결과로 읽기 전 능력을 소급 변경 |

자기평가는 기존 ‘안다/모른다’로 유지한다. 객관식 응답과 별도 증거로 기록한다.
객관식으로 추론 선택지를 구별한 결과를 자유롭게 증명할 수 있는 능력으로 해석하지 않는다.

## 2.2 문항 설계서에 필요한 내용

| 필드 묶음 | 기록할 내용 |
| --- | --- |
| 측정 주장 | topic, concept, ability, 수행 목표, 성공/실패의 해석 |
| 과제 조건 | prior-knowledge / provided-information, phase, 언어, 시간·도구 조건 |
| 문항 가족 | item_family_id, 수치만 바꾼 변형끼리의 연결 |
| 내용 | 질문, 보기, 정답, 해설, 오개념, 채점 기준 |
| 출처 | 본문/개념 근거의 역할, book/edition/section/source ID, 정확한 위치와 hash |
| 생성 이력 | model, prompt, input/config hash, generation ID |
| 품질 이력 | 자동 검사, AI 검토, 사람 검토, 실제 응답 통계 각각의 상태 |
| 실험 용도 | train/dev/evaluation, 사전/사후, 노출·피드백 여부 |

`target_difficulty`는 출제 의도다. `observed_item_statistics`와 별개이며 실측값은 응답 전에는 null이다.
정답률을 기록해도 소수 참가자의 결과를 보편적 문항 난도로 확정하지 않는다.

## 2.3 기존 계약을 재사용하는 범위

확인한 `concept-question-spec-v2`와 `generated-question-v5`는 다음을 이미 갖췄다.

- 개념·능력·수행 목표·오개념·목차 참조·입력 해시.
- Markdown/LaTeX, 4지선다, 정답 인덱스, 내용 ID.
- AI 검토와 사람 검토의 구분, immutable import/snapshot.

현재 제약:

1. v5 `measurement_context`는 **prior-knowledge만 허용**한다.
2. 현재 ConceptBlueprint는 동일 개념·능력 셀의 중복을 거부한다. 병렬 문항을 한 blueprint에 넣을 수 없다.
3. 기존 v4 지문형 경로는 제한된 단일 지문·apply 용도다. 임의의 사후평가 전부를 지원하지 않는다.
4. 기존 9문항 선택은 전이기 영역 제약을 포함한다. 새 실험의 문항 수와 균형 정책으로 자동 간주하지 않는다.
5. 영어 생성 정책은 유지한다. 한국어 표시 번역을 도입하면 별도 표현 버전/검토와 실험 언어 통제가 필요하다.

첫 실험의 권장 구현은 **기존 v5 사전 진단 + 별도의 오프라인 사후평가 packet**이다.
사후평가용 내부 설계서 이름은 제안 단계이며 공개 API 버전으로 확정하지 않는다.
온라인화할 때 새 계약/adapter/migration을 설계하고 v4/v5 호환 회귀검사를 추가한다.
v5 필드 제약을 몰래 완화하거나 과거 문항 ID에 새 내용을 붙이지 않는다.

## 2.4 문항 작성 파이프라인

1. 전공 관점에서 주장·루브릭·오개념 정의.
2. 사용할 원문/범위/권리·언어와 설계서를 고정.
3. 모델이 후보를 생성하거나 로컬 초안을 작성. 생성 출처를 정확히 기록.
4. 형식·정답 인덱스·중복 보기·수식·해시·정답 노출 자동 검사.
5. 수학 계산 가능한 부분은 계산으로 교차 확인. 이것만으로 문항 타당성은 증명되지 않는다.
6. AI 검토를 별도 기록하고 전공 검토자가 정답/조건/목표 적합성을 판단.
7. 문항 가족·사전/사후·개발/평가 분할을 고정하고 승인 범위에 맞게 발급.
8. 응답 후 오답·천장/바닥 현상·부담을 살펴 수정 후보를 만든다. 새 버전으로만 변경.

사람 검토자가 없으면 ‘AI 검토된 예비 문항’ 상태로 시연할 수 있지만 사람 검증 완료로 말하지 않는다.
모델이 자기 생성 문항을 맞혔다는 사실도 독립적인 정답 검증이 아니다.

## 2.5 작은 출제 계획 초안

첫 조사 범위: 3개 개념 × meaning/application/reasoning. 전체 분야를 평가한다고 주장하지 않는다.
보유 18문항 중 해당 셀의 질문을 검토해 재사용 여부부터 결정한다.

- 면담 전: 대표 사전 문항 3개와 사후 문항 설계 3개를 나란히 설명. 사후 문항은 실제 생성 완료로 표시하지 않음.
- 예비 실험 준비: 선택한 9개 셀에 대해 사전 문항 후보와 독립적인 평가 문항 후보를 설계.
- 실제 문항 수: 참가자 부담을 예비 시행으로 확인하고 확정. 18문항 응답을 모든 사용자에게 강제하지 않음.
- 파일럿 점수: 셀별 응답/정답/미평가를 제시. 전체 숙련도나 보정된 난도 점수는 산출하지 않음.

일반화된 사후 목표가 ‘자료를 덮고 새로운 문제에 적용’인지, ‘자료를 보면서 이해’인지 먼저 고른다.
첫 제안은 일정한 열람 시간 뒤 자료를 덮고 새로운 적용 과제를 수행하는 것이다.
현재 v4 `provided-information`은 이를 자동으로 구분하지 못하므로 실험 phase/접근 조건을 별도로 저장한다.

## 2.6 평가가 오염되지 않도록

- 사전 정답 피드백은 사후평가가 끝난 뒤 제공한다.
- 사전/사후에 숫자만 바꾼 같은 가족 문항을 배치하지 않는다.
- 독립 전공 검토자가 평가 문항을 만들거나 검토하되 시스템 추천 순위를 보지 않는다.
- 같은 책의 판본·번역·유사 절과 같은 문항 가족은 데이터 분할 시 함께 묶는다.
- 추천 시점에는 사후 정답·참가자의 이후 행동·정답 평가 라벨을 입력하지 않는다.
- 원문 언어·번역 상태·피드백·열람 시간·이전 노출을 기록한다.
- 실제 읽기 전후 변화에는 연습효과와 문항 차이가 섞인다. 대조 설계 없이 학습 효과로 단정하지 않는다.

## 2.7 예시: 측정 주장 연결 (합성 설계 예시)

주장: ‘독자는 선형독립의 정의를 새 벡터 집합에 적용할 수 있다.’

사전 과제: 정의를 제시하지 않고 간단한 벡터 집합의 독립성 판별과 근거 선택.
관찰: 선택지·정답·수행 조건·해당 문항 ID. 한 문항 정답은 한 번의 수행 관찰이다.
책 분석: 해당 절이 정의를 도입하는지, 가우스 소거법을 전제하는지 원문 위치로 기록.
사후 과제: 읽은 예제와 다른 맥락에서 독립성 판별. 사전 과제와 다른 문항 가족 사용.
평가 질문: 예상한 독자–절 적합성과 실제 수행/부담이 일치했는가.

이는 출제 설계 예시다. 정답이 검토된 실제 문제은행이나 사용자 결과가 아니다.
