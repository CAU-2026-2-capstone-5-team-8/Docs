# 1. 추천 원리와 모델 선택

상태: 설계 제안. 이 문서는 추천 코드 변경이나 새 모델 학습 결과가 아니다.

## 1.1 원래 문제 정의 유지

주제 선택 → 독자 진단 → 책 분석 → 매칭이라는 구조를 유지한다.
다만 독자 수준과 책 수준을 각각 임의의 0~100점으로 만든 뒤 빼지 않는다.
서로 같은 척도라는 근거가 없기 때문이다.

독자, 책의 속성, 학습 목표를 따로 기록한다. ‘좋은 매칭’의 첫 검증 대상은
**지정한 학습 목표에 대해, 이 독자가 이 자료로 시작하는 것이 적절한가**다.
책 전체에 보편적인 절대 난이도를 부여하는 것은 첫 목표에 포함하지 않는다.

## 1.2 현재 구현과 부족한 부분

| 항목 | 확인한 현재 구현 | 남은 부분 |
| --- | --- | --- |
| 독자 | 개념 × meaning/application/reasoning별 prior-knowledge 정답·응답 수 | 적은 문항의 불확실성, 독립 문항에서의 예측력 |
| 책 | 개념 매칭, 검토된 그래프의 선수개념 후보, 출처 보존 | 본문에서 실제로 전제하는 수행, 설명 방식 |
| 매칭 | 준비도 범주 → 복습 여부 등 → 도서 ID의 결정적 정렬 | 같은 범주 책의 실질적 차이, 사용자의 학습 목표 입력 |
| 근거 | 체크리스트와 입력/결과 snapshot | 근거의 정확성·완전성에 대한 독립 평가 |
| 결과 | API·DB·화면 연결 | 독자에게 더 나은 추천이라는 성능 근거 |

현재 ML 기준점은 `88b0177`의 `concept-learning-v2`다. 기존 v1이나 과거 rank API의
수치 평가를 새 정책의 정확도로 인용하지 않는다.

## 1.3 추천의 비교 항목

| 항목 | 독자 측 관찰 | 책/장 측 관찰 | 주의 |
| --- | --- | --- | --- |
| 사전 지식 | 개념을 설명/구별/적용한 응답 | 설명 없이 사용하거나 명시적으로 요구하는 지식 | 목차 등장은 전제 지식의 증거가 아님 |
| 수행 요구 | 계산, 적용, 근거·반례 판단 | 본문·예제가 요구하는 구체적 수행 | 능력 명칭을 자동으로 쉬움/어려움 순서로 간주하지 않음 |
| 설명 지원 | 관찰된 어려움 | 정의 도입, 풀이 예제, 생략된 단계 등 | 예제 수만으로 교육적 충분성을 확정하지 않음 |
| 목표 부합 | 무엇을 배우려는지 | 해당 학습 목표를 다루는 위치와 수행 | ‘application’ 선택만으로 ML 응용 목표를 안다고 가정하지 않음 |
| 언어·읽기 부담 | 표시 언어와 해당 언어 경험 | 실제 읽을 원문·수식·문장 | 번역문의 난도를 원문 난도로 대체하지 않음 |

‘계산 가능/추론 가능’은 다른 수행이다. 셋을 자동으로 1·2·3 레벨로 변환하지 않는다.
관찰한 문항·조건·횟수와 부족한 정보를 함께 보존한다.

## 1.4 책 분석의 단위

**첫 실험은 책의 일부 장/절을 단위로 한다.** 실제 본문을 확보하고 판본·절·분석 범위를 고정한다.
부분 발췌를 분석했다면 해당 부분에 대한 판단만 가능하다. 책 전체 추천으로 확장할 때에는
장 표본의 대표성과 다른 장의 요구사항을 별도로 확인해야 한다.

모델이 제안할 속성은 다음과 같다.

- covered: 이 부분에서 다루는 개념.
- assumed: 설명 없이 사용하는 것으로 관찰된 개념/수행. 근거가 없으면 unknown.
- introduced: 이 부분에서 정의나 설명을 도입하는 개념.
- practiced: 예제·연습에서 요구하는 수행.
- support: 정의·풀이 예제·중간 단계의 제공 여부와 근거 위치.

여러 속성이 동시에 성립할 수 있다. 앞부분에서 설명하고 뒷부분에서 사용하는 경우도 있다.
‘introduced=true’는 ‘독자가 충분히 배웠다’와 다르다. 분석 범위 안에 설명이 없다는 관찰도
책 전체에 설명이 없다는 뜻은 아니다.

## 1.5 첫 매칭 후보: 검토된 속성을 이용한 비교

이 정책은 **아직 가설**이다. 현재 v2와 비교하며 좋은 결과가 확인될 때만 도입을 검토한다.

1. 주제·학습 목표·분석 범위가 맞는 후보를 모은다.
2. 관찰된 전제 요구와 독자의 수행을 대응시킨다. 서로 다른 문항의 정답률을 공통 난도로 보지 않는다.
3. 미평가인 요구와 실제 오답이 관찰된 요구를 분리한다.
4. 부족한 개념을 자료 안에서 도입하는지와 설명 지원이 있는지 함께 제시한다.
5. 목표 부합과 관찰된 부담에서 한 후보가 다른 후보보다 명확히 낫다고 볼 수 있을 때 우선한다.
6. 교환관계가 있거나 근거가 부족하면 ‘비교 보류/같은 후보군’으로 표시한다.

정확한 지배 조건·범주 기준은 작은 비교 사례에 독립적인 판단을 붙인 뒤 개발 세트에서 정한다.
임의 가중치를 ‘과학적으로 검증된 점수’로 표현하지 않는다. 동일 후보군의 안정적 표시 순서는
품질 순위가 아니다. unknown을 0점으로 채우거나 자료 없는 책을 나쁜 책으로 취급하지 않는다.

가상 설명 예시: ‘행렬 계산 수행이 확인됐고 A절은 아직 미평가인 벡터공간을 정의부터 도입한다.
B절은 이를 설명 없이 사용하는 부분이 있어 A절을 먼저 검토할 후보로 제시한다.’
실제 문장으로 사용하려면 각 진술의 문항 응답·본문 근거가 모두 있어야 한다.

## 1.6 AI 모델이 맡을 역할

| 선택지 | 개발 방법 | 데이터 요구 | 이번 일정의 판단 |
| --- | --- | --- | --- |
| 기존 규칙 | 현재 v2를 고정해 비교 기준으로 사용 | 현재 입력 | 면담용 결과 재현에 사용 |
| 사전학습 모델의 구조화 추출 | 고정 프롬프트로 위 속성과 원문 위치를 JSON 출력, 검사·검토 | 사용 가능한 본문, 속성 판정 기준, 독립 정답 | 첫 실험 후보. 모델·비용은 아직 미정 |
| BERT 계열 분류기 학습 | 문단을 속성별로 라벨링, 분리된 자료로 학습/평가 | 충분한 사람 라벨, GPU/실행시간 | 금요일 필수 범위 아님. 데이터 준비 후 비교 후보 |
| 해석 가능한 통계 매칭 | 검토된 속성 차이로 독자–자료 적합성 예측 | 실제 독자–자료 판단/읽기 결과 | 데이터 수집 뒤 검토 |
| IRT/Rasch | 문항 반응으로 능력과 문항 난도를 공동 추정 | 연결된 응답 설계, 충분한 자료와 모형 검증 | 현재 자동 도입하지 않음 |

BERT가 문장 분류나 표현을 맡아도 ‘좋은 추천’의 정답은 별도로 필요하다.
LLM의 자기신뢰도는 통계적 신뢰구간이 아니며, 프롬프트 난도는 실측 난도가 아니다.
모델 선택보다 출력 속성과 평가 기준을 먼저 고정한다.

실험 실행 시 model/provider revision, prompt/config hash, 입력 hash, 출력 원본, 실행 시각,
재시도·토큰·비용을 기록한다. 고정 설정도 외부 모델의 완전한 재현성을 보장하지 않으므로 원출력을 저장한다.
외부 전송은 자료별 사용 조건과 기존 프로젝트 승인 범위를 먼저 확인하고, 이번 설계 단계에서는 호출하지 않는다.

### 처음 모델 실험을 개발하는 구체적 순서

1. 실제 절 2~3개로 사람이 속성·원문 위치를 표시해 출력 예시를 만든다. 이 단계는 기준을 다듬는 개발 자료다.
2. 추출 schema를 정의한다. 예: concept, role, task, passage_id, start/end, supporting_quote, unknown_reason.
3. 프롬프트에는 정의·허용값·개발 예시·‘없으면 unknown’ 규칙을 넣는다. 평가용 정답 예시는 넣지 않는다.
4. 모델 adapter는 명시적 입력 파일만 읽고 JSON을 출력한다. 모델이 파일/웹을 임의 탐색하도록 두지 않는다.
5. quote와 offset이 원문에 실제 존재하는지 검사한다. 존재한다고 그 해석까지 맞는 것은 아니므로 내용 검토도 한다.
6. 서로 다른 책의 남겨둔 절에서 규칙 기반 추출과 비교한다. 속성별 오류와 처리 불가를 따로 낸다.
7. 수정은 개발 자료에서 하고 새 prompt/config 버전을 부여한다. 평가 자료에 맞춰 반복 수정하면 새 평가 자료가 필요하다.

처음부터 새 모델을 훈련할 필요는 없다. API 기반 추출도 모델 활용이지만 미세조정과 구분한다.
추출 품질과 비용이 만족스럽지 않을 때, 어떤 속성에서 오류가 나는지 확인한 뒤 모델 교체나 학습을 결정한다.

## 1.7 근거가 있는 설계와 연구의 적용 범위

- [ECD 실제 평가 설계 사례, ETS 2018](https://www.ets.org/research/policy_research_reports/publications/report/2018/jzuw.html): 측정할 주장·관찰 증거·과제를 연결하는 접근을 참고한다. 우리 진단의 타당성을 대신 입증하지 않는다.
- [Concept Bottleneck Models, ICML 2020](https://proceedings.mlr.press/v119/koh20a.html): 사람이 해석할 수 있는 중간 개념을 통해 판단하는 설계를 참고한다. 이번 규칙+추출기를 해당 논문의 학습된 CBM이라고 부르지 않는다.
- [Reader–text interaction, 2016](https://aclanthology.org/W16-4105/): 독자 특성과 글의 복잡성을 실제 읽기 결과에 연결해 평가한 연구다. 특정 언어·실험의 수치를 우리 기술서적에 이식하지 않는다.
- [독자와 텍스트의 공동 측정](https://link.springer.com/chapter/10.1007/978-981-19-3747-7_11): 공통 척도가 필요한 이유를 참고한다. 현재 자료로 책의 IRT 난도를 추정했다는 뜻이 아니다.

## 1.8 교수에게 확인받을 결정

A. 첫 기여를 ‘설명 가능한 개념/수행 매칭’으로 둘지, ‘공통 난도 척도 추정’까지 요구하는지.
B. 일부 장/절에 대한 추천으로 범위를 좁혀도 되는지.
C. 학습 목표 하나와 선형대수 하위개념 몇 개로 시작해도 되는지.
D. 독립적인 전공 검토자를 확보할 수 있는지.

제안 기본값은 A의 전자, B 허용, 선형대수의 행렬·선형독립·기저 중 본문 확보 가능한 범위다.
이는 사용자의 확정 선택이 아니라 기존 자산을 재사용하기 위한 초안이다.
